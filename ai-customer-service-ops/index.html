Cutting case resolution time by 90% with a GenAI assistant on top of RPA

Role: Product Manager. Domain: customer service operations for two regulated back-office processes.

Problem

A customer operations team handled over 100,000 cases a year across two regulated processes. Each case took 50-60 manual steps passed between four or more teams, and 3-5 days end to end. Errors were costly because the data was sensitive.

Approach

Phase 1: RPA bots. Bots automated the rule-based steps, including logins to government portals, with human validation between handoffs. Handling time dropped about 70%.

Phase 2: GenAI assistant. Two gaps remained. Reading notes, checking documents, handling exceptions and writing handoffs still needed people. And the bots ran once a night, so a case created after the cutoff waited for the next run. An assistant that agents run at any time, and that triggers the same bots, closed both gaps.

How a case flows

  1. An agent opens a case and starts the assistant at any time.
  2. A small, fast model classifies the case, extracts fields and checks completeness.
  3. If something is missing, the assistant drafts a request and a person sends it.
  4. A larger model summarizes the case and proposes the update, using only the case record.
  5. The agent approves, edits or rejects. Sensitive updates always need human approval.
  6. On approval, the assistant triggers the bot, which runs the steps and logs the result.
  7. The assistant drafts the handoff note for the next team.

Choosing the stack

I scored three options on accuracy, security, cost at volume, integration effort and flexibility, using a golden set of about 500 historical cases: platform-native AI only, a single large cloud LLM, and platform-native orchestration with a two-tier LLM. The third won on cost per case, security and the ability to swap models. Token cost was small, so security and accuracy drove the decision.

Risk and governance

  • Sensitive identifiers were masked before any model call.
  • Outputs were structured and schema-checked, and notes were treated as untrusted input.
  • Launch gates: at least 95% field accuracy and zero privacy leakage in red-team tests.
  • Staged rollout by case type, with a kill switch.

What I learned

  • Standardizing case templates mattered as much as model choice.
  • Shadow mode with accept, edit and reject signals turned skeptics into champions.
  • Freed capacity is not cash: it was redeployed, so net savings are smaller than capacity value.
